# Bench testing — Custom R02

**Normal R02 has been programmed and booted successfully on the original controller. Not a hardware-qualified production image.** The C reconstruction is functionally compared in software, not byte-identical to factory. The optional profiling build adds timing overhead and should not be the initial test.

## Preparation

- Keep the original complete, known-board 64 KiB HEX and the working programming/recovery procedure. Verify controller/MCU revision. Never use another board's identity or calibration. A programming operation may erase the whole flash even if only application bytes are supplied; confirm the programmer's actual erase scope and verification behavior.
- The full image generated from the supplied backup preserves 0x7A00–0xFFFF byte-for-byte. The stored identity is populated and the enrollment marker is inactive. Original/rebuilt device-ID logic matched in modeled success/failure cases; the normal build passed startup on the original controller, but broader hardware identity compatibility is unverified and a genuine mismatch will still halt. If the device has been changed or recalibrated after the capture, this restores the captured state rather than the present physical board's latest state.
- The supplied backup's active record has CR_UART, 115200, address E0, Kp 65535, Ki 1, Kd 1638, protection disabled, origin mode disabled and saved motion FFFF (no saved UART motion). The Kp value is atypical; the raw representation is preserved by request. Do not enable or command motor movement with this configuration. Inspect and correct tuning using the existing configuration functions before motor testing. The factory fallback Kp is 1638, not a universal safe gain. Validate actual motor, current limits, protection and calibration for your setup.
- Use a controlled bench with independently interruptible drive power and the mechanism unloaded. Logic-only testing without motor power/connection is preferable only where the board supports it. Do not bypass startup diagnostics to force an unhealthy board into operation. Keep a physical means of removing drive power.

## Sequence

1. Use the previously verified HC32L130 programmer and recovery connection. Program only the **normal Custom R02** full HEX for the exact board, verify all flash bytes/readback against the candidate, then leave programming mode as in the original recovery procedure. If programming or verification fails, do not attempt motion; restore the original capture.
2. Check normal initialization, display, error screens, existing menus, SysInfo and button navigation. No startup logo is expected. If an encoder/magnet startup error appears, the new R02 screen clears after approximately 10 seconds (or Menu/Enter) and opens settings with the drive locked. Confirm actual outputs remain de-energized with drive power isolated; no UART is expected during the lock. Correct the magnet and restart before any motor test. Other startup diagnostics and device-ID mismatch halts are unchanged.
3. Confirm SysInfo values match the active stored configuration. Read the UART using the documented read-only requests before using any setter. Check enable state, protection and calibration. Verify Kp and current configuration before any drive operation.
4. Verify motor-disabled behavior, output stages and current sensing before applying drive power. Perform controlled unloaded low-speed movement only after the electrical and tuning checks, and stop immediately for abnormal current, heat, noise or unexpected movement. Verify stall and emergency power removal independently. Compare against known stock behavior.
5. On a successful healthy boot, check that Next toggles between RPM and the original pulse display; check RPM against an independent tachometer at low unloaded speed. Check that original menus, UART, settings save/load, calibration and origin behavior remain available. These are not all physically validated yet. Test persistence only when it is safe to change a setting.
6. After successful baseline hardware operation, optionally repeat with the **Profile R02** image. The Perf page samples motion IRQ workload and peak duration; it does not measure total CPU utilization and adds ISR timing overhead. Do not use it for the first motor-control test or under load until verified.

If the controller fails to boot or behave normally, remove drive power and restore the original HEX via the known programming method. Verify the restored full flash, not only the application. There is no claim of validated recovery from arbitrary interrupted programming.
