# Hardware validation gates

The project is independently editable and compiles without the factory executable. It is not a deployable replacement yet. Before experimental hardware operation:

1. Keep the available original full main-flash capture private and retain a known-working restoration procedure. If a future read of the same board is possible, compare independent captures before any programming; a converted BIN is not a second capture. A second capture is not required for offline source work.
2. Review the actual HC32L130 flash-controller behavior (including status flags, erase/program timing, alignment and failures), the programmer's erase scope and readback verification. An application-only address range does not guarantee the ISP utility preserves the reserved pages. Never assume it does. Preserve identity, settings and calibration per device; do not copy these from another unit.
3. For a production derivative, resolve the legacy flash error propagation gap and test interrupted settings commits and calibration validity. The factory reconstruction intentionally retains original behavior. Current tests use an idealized NOR model and do not establish safe recovery. Audit shared interrupt/foreground state, worst-case timing and nested stack usage; instruction counts are not real hardware timing.
4. Establish a safe bench setup with a healthy expendable controller, current-limited isolated supply, motor disconnected for logic-only tests where the hardware permits it, and a means to cut drive power independently. Validate reset, GPIO, OLED, UART, ADC and PWM idle states before motor-power operation. Do not use a damaged H-bridge as a validation target. Keep protective checks enabled and do not bypass startup error conditions.
5. Verify original and reconstructed interrupt timing and actual drive waveforms with suitable instrumentation before connecting the motor. Validate current sensing and fault behavior first, then controlled unloaded movement, calibration, homing and loaded operation. Stop on abnormal heating, current or uncontrolled motion.
6. Verify all supported board revisions and applicable redistribution rights before publishing a release. The original source names/comments and vendor licensing cannot be inferred from a binary dump.

No experimental HEX or BIN is generated by this audit package. The original factory backup in the cumulative reference project is not a universal image. Hardware-testable build and deployment procedures are intentionally gated on the above checks.
